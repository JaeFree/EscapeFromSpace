# 진행 기록

다음 세션은 이 파일과 `docs/PLAN.md`를 읽고 시작한다. 대화 기록은 PC 사이에 이어지지 않는다.

## 지금 상태 (2026-11-19 기준)

- **가장 최근 (2026-11-19)**: 사용자가 다른 PC에서 테스트한 뒤 세 가지를 요청했다. ① 대기실 창고 그림이 벽 밖으로 삐져나옴 → 그림을 판정 크기에 맞춰 줄이고 (2, 12)로 옮김. ② 무게 감속이 너무 셈 → 50%부터 15%, 10%마다 7%씩, 하한 30%로 완화 (GDD 6.4 표 갱신). ③ 시작 화면과 스토리 장면 → `Title` 씬(빌드 맨 앞, 이어하기/새로 시작·설정·종료)과, 프롤로그·엔딩을 장마다 코드로 그린 픽셀아트 장면 + 자막 + 오른쪽 위 건너뛰기 버튼으로 바꿈 (GDD 13.3·14.1, PLAN 40~43단계). 배치 모드 에셋 생성과 임시 플레이 모드 테스트(시작 화면 → 대기실 → 프롤로그 → Esc 건너뛰기에 설정 창이 안 열림 → 엔딩 → 건너뛰기 버튼)를 통과하고 캡처로 확인했다. 45단계와 함께 커밋했다.
- **9부 55단계 (진행 중, 2026-11-19)**: README와 `docs/COMBAT.md`에 9부 기능(은신, 에일리언, 이변, 무작위 배치, 로봇 개, 설계도)을 더했다. 자동 플레이어 재측정은 PC 메모리 부족으로 중간에 멈췄다 (피스톨·방어구 없음 화물칸 1판만: 5/5 처치, HP 56). 다시 돌리기와 Windows 빌드는 남았다. 지금 `Builds/`의 exe는 46단계 때 것이라 9부가 들어 있지 않다.
- **9부 54단계 데이터 칩과 설계도 (2026-11-19)**: 배마다 함선 단말기 1개(고정 자리, E 3초 해킹, 해킹 중 1초마다 반경 5칸 소리, 판마다 한 번)에서 데이터 칩이 나온다. 연구 컨테이너 10%, 네임드 잔해 40%. 칩을 가지고 탈출하면 칩마다 아직 없는 설계도 하나를 무작위로 등록하고 칩은 사라진다(결과 화면에 "새 설계도"). 다 모으면 칩은 팔기만 한다. 제작소에 설계도 6종(소음기, 홀로그램 미끼, EMP 수류탄, 메디킷, 산소 캔, 2단계 헬멧) 줄을 더했고, 설계도가 없으면 "설계도 필요"로 잠긴다. 복사본에서 7개 단말기 자리, 3초 해킹과 소리 3번, 칩 2개 → 설계도 2개 등록을 확인했다.
- **9부 53단계 보관함 확장과 로봇 개 (2026-11-19)**: 한의 퀘스트 4·9·16 보상으로 보관함 2칸(2×1)·4칸(2×2)·6칸(3×2). 새 퀘스트 21 "고철 사냥개"(오토, 채굴선 방문 다음 순서): 채굴선 구석 (125.5, 29.5)의 부서진 로봇 개에서 코어를 들고 나와 납품하면 로봇 개가 합류한다. 개는 자취를 밟아 따라다니고(12칸 넘게 떨어지면 옆으로 순간 이동), 등의 가방 3칸(최대, 사용자 결정)은 무게에 들지 않고 죽어도 남는다. 싸우지 않는다. 가방 화면 오른쪽에 보관함 아래로 "로봇 개" 칸이 생기고 창이 넓어진다. 저장 파일에 보관함 크기·개 여부·개 가방을 더했다. 복사본에서 확인하고 가방 화면을 캡처했다.
- **9부 51·52단계 우주선 이변과 에일리언 (2026-11-19)**: 대기실 출격 창을 열 때 이변을 뽑아 보여 주고(없음 40, 정전 25, 보안 경계 20, 에일리언 습격 15; 배 2척, 아이템 +25%), 정거장의 `RaidEventDirector`가 적용한다. 정전: 그 배 안에서 6칸만 보이는 어둠, 로봇 시야 0.6배와 손전등 원뿔. 보안 경계: 로봇 2기 추가(5→7), 듣는 반경 1.5배. 에일리언 습격: 일반 로봇을 에일리언으로. 배에 들어가면 위쪽에 "정전 — 화물선 잔해" 알림. 에일리언 2종(스토커: 근접·빠름·귀 밝음, 스피터: 0.6초 충전 뒤 초당 8칸으로 날아가는 산성 침), 사체(1×2, 에일리언 조직 60%), EMP·어둠 무효. 병원선·연구선의 일반 적은 늘 에일리언 (StationLayout, 옛 씬은 다시 만든다). 그림은 코드로 그린 점 그림. 수치는 `RaidConfig`의 우주선 이변 칸과 `AlienStalker`·`AlienSpitter` 에셋. 복사본에서 세 이변과 스피터 명중을 확인하고 정전 화면을 캡처했다.
- **9부 50단계 은신 2 (2026-11-19)**: 소음기(총구 칸, 총소리 8→3칸, 반동 −5%, 연구 컨테이너 3%), 홀로그램 미끼(도구칸 4, 커서 쪽 8칸에 6초 동안 내 모습, 1초마다 반경 10칸에 소리를 내서 로봇이 의심하고 살피러 옴, 일반·연구 컨테이너 5%), EMP 수류탄(도구칸 5, 1초 뒤 반경 3칸 로봇 4초 정지, 에일리언 무효, 연구 컨테이너 5%). 도구칸을 5개로 늘렸다(키 4, 5). 대기실에서는 미끼·EMP를 쓰지 않는다. 복사본에서 로봇이 미끼 자리로 가서 의심하고, EMP에 4초 멈춘 뒤 풀리는 것을 확인했다. GDD의 "미끼를 쏘기도 한다"는 넣지 않았다(로봇 사격이 플레이어만 겨누게 되어 있어서. 대신 살피러 간다).
- **9부 49단계 은신 1 (2026-11-19)**: 발견 게이지(머리 위 "?"와 막대, 3칸 안 0.5초~시야 끝 2초)와 의심 상태(절반을 넘거나 발소리를 들으면 그곳에 가서 3초 둘러봄), 살금 걷기(Ctrl, 속도 50%, 발소리 없음), 발소리(걷기 4칸, 구르기 5칸; 들은 로봇은 의심만), 엄폐(적 쪽 양옆 1칸 안 벽·엄폐물, 로봇 퍼짐 3배와 게이지 0.5배, 엄폐물이 하얗게 빛남), 뒤에서 베기(알아채지 못한 적에 광선검 3배). 수치는 `CombatConfig.asset`의 은신 칸. 테크 트리 은신 갈래 6노드도 넣었다(조용한 발 I·II, 그림자 I, 암살자, 위장막, 유령; 창이 화면보다 크면 줄여 보인다). 소음기용 `ItemData.NoiseRadius`와 총소리 반경도 준비했다(아이템은 50단계). 복사본에서 정면 8칸 1.5초 발견, 등 뒤 걷기 → 의심, 살금 걷기 → 무반응, 뒤에서 베기로 권총 로봇 한 번에 파괴를 확인했다.
- **9부 48단계 무작위 배치 (2026-11-19)**: `RaidLayoutRandomizer`(정거장 씬 `RaidLayout` 오브젝트)가 판마다 로봇 순찰 경로와 컨테이너 자리를 섞는다 (GDD 19.2). 수·종류는 씬 그대로, 자리만 바꾼다. 로봇 시작점은 출입구에서 구역 안 걸음 10칸(네임드 12칸) 이상, 무리끼리 6칸, 순찰점 사이 6~15칸, 저격은 앞이 12칸 트인 칸. 컨테이너는 한쪽만 벽에 붙은 칸, 서로 4칸, 출입구 3칸(연구 10칸), 포드·레버 2.5칸. 못 찾으면 조건을 반씩 풀고, 그래도 없으면 원래 자리. 시드는 로그에 남고 Inspector의 Fixed Seed로 같은 판을 다시 볼 수 있다. 복사본에서 3판을 돌려 67개 위치가 모두 바뀌고 35기가 모두 생기며 벽 안·출입구 앞에 선 로봇이 없는 것을 확인했다.
- **9부 47단계 컨셉 변경 (2026-11-19)**: 정거장 → 행성 케르-7의 우주선 무덤 (GDD 19.1). 프롤로그·엔딩·퀘스트 글·상인 인사·구역 이름(추락 지점, 화물선 잔해, 이민선, 병원선, 연구선, 군 순찰선, 채굴선, 연료 수송선)·도약 엔진·방어망 해제 코드·귀환 비콘·출격 해치로 바꿨다. 스토리 장면을 새로 그렸다 (행성과 센티널 위성, 위성의 공격, 협곡 불시착, 배 안의 생존자 / 엔진 점화, 협곡에서 이륙, 위성 사이로 탈출, 멀어지는 행성). 시작 화면 배경은 협곡의 우주선 무덤. 배 사이 길의 바닥은 코드로 그린 모래 타일(`Floor_Sand`). 기존 에셋은 `ProjectSetup.Concept.cs`의 `ApplyWreckFieldTexts`·`ApplyWreckFieldStation`이 옛 글이 그대로일 때만 바꾼다. 복사본에서 실행해 에셋을 바꾸고 캡처로 확인한 뒤 저장소로 복사했다.

- **45단계 난이도·전체 맵 (2026-11-19)**: 사용자가 플레이 뒤 "너무 어렵다, 로봇 HP와 공격 텀을 낮추고, 미니맵 가독성·지금 구역 이름·포드 상시 표시"를 요청했다. 에디터가 열려 있어서 프로젝트를 임시 폴더에 복사해 자동 플레이어로 7구역을 조합별로 돌렸다. 로봇 12종(네임드 포함)의 HP 0.8배, 쉬는 시간 2배로 바꿨다 (기록·표는 GDD 11.3). 전체 맵(M)은 한 화면에 맞추고, 구역별 바닥 색, 현재 위치 이름과 구역 테두리, 가 본 구역 이름, 포드 상시 표시, 범례를 넣었다 (GDD 9.2, `MapUI.cs`). 복사본에서 캡처로 확인했다. 침실 입구의 N-3 매복과 구역당 로봇 7~9기는 기록만 하고 바꾸지 않았다. 이어서 사용자 결정으로 구역마다 로봇 5기(일반 로봇만 줄임, 51→35기)와 N-3 순찰 시작점을 침실 안쪽 (20, 45)로 옮겼다 (`StationLayout`, `ProjectSetup.Named`의 `ApplyFiveRobotsPerZone`). 복사본에서 `ProjectSetup.Run`으로 Station 씬을 고쳐 저장소로 복사했다. 동력 구역의 P-X 무리와 AR 로봇 순찰 경로도 출입구에서 먼 곳으로 옮겼다 (GDD 11.3). 40~45단계를 커밋했다 (push는 아직).

## 작업 방식에서 알게 된 것

- **사용자에게 확인을 부탁하기 전에 직접 돌려서 확인한다.** 1단계에서 컴파일만 확인하고 넘겼다가 맵이 안 보이고 벽을 통과하는 문제가 사용자에게 넘어갔다. 그 뒤로는 Unity 배치 모드에서 임시 플레이 모드 테스트를 돌린다.
- **배치 모드는 Unity 에디터가 닫혀 있어야 돈다.** 열려 있으면 사용자에게 닫아 달라고 한다. 닫기 전에 Inspector에서 바꾼 값은 `Ctrl+S`로 저장해야 파일에 반영된다.
- **컴파일과 에셋 생성**:
  `Unity.exe -batchmode -quit -projectPath <저장소> -executeMethod EscapeFromSpace.EditorTools.ProjectSetup.Run -logFile <로그>`
  로그에서 `error CS`와 `Exception`을 찾는다. Unity 설치 경로는 PC마다 다르므로 저장소에 적지 않는다.
- **임시 플레이 모드 테스트**: `Assets/TempTests/`에 asmdef와 테스트 파일을 두고
  `Unity.exe -batchmode -projectPath <저장소> -runTests -testPlatform PlayMode -testResults <xml> -logFile <로그>`로 돌린 뒤 폴더를 지운다 (커밋하지 않는다).
  - asmdef: `references`에 `UnityEngine.TestRunner`, `UnityEditor.TestRunner`, `Unity.InputSystem`, `precompiledReferences`에 `nunit.framework.dll`, `overrideReferences` true, `defineConstraints`에 `UNITY_INCLUDE_TESTS`.
  - 게임 코드에 asmdef가 없어 테스트는 게임 타입을 직접 참조하지 못한다. `GameObject.Find`, `GetComponent("Health")`, 리플렉션, `SendMessage`를 쓴다.
  - 입력은 `InputSystem.QueueStateEvent`로 `KeyboardState`, `MouseState`를 넣는다. 배치 모드에서는 `InputSystem.settings.backgroundBehavior = IgnoreFocus`와 `editorInputBehaviorInPlayMode = AllDeviceInputAlwaysGoesToGameView`를 먼저 설정해야 입력이 들어간다.
  - 화면 확인은 `Camera.main`을 RenderTexture로 렌더링해 PNG로 저장한다. 캡처는 프레임을 길게 멈추므로 시간 측정 구간에 넣지 않는다.
  - 컴파일 에러가 있으면 `-runTests`가 끝나지 않으므로 타임아웃을 건다.
- **배치 모드에서 씬을 열면 그 전에 잡아 둔 에셋 참조가 무효가 된다.** 씬을 연 뒤에 `AssetDatabase.LoadAssetAtPath`로 다시 불러온다.
- **배치 모드에서 타일을 칠한 뒤에는 벽 충돌체를 직접 만들어야 한다** (`ProjectSetup.EnsureWallColliders`). 안 하면 합쳐진 충돌체가 빈 채로 저장되어 벽을 통과한다.
- **속도는 한 스크립트에서만 쓴다.** 두 스크립트가 각자 `linearVelocity`를 쓰면 실행 순서에 따라 한 틱이 덮인다 (구르기가 2.85칸만 가던 원인).
- **플레이어 충돌체에는 마찰 0 재질을 쓴다** (`Assets/Physics/NoFriction`). 기본 마찰이면 벽에 비스듬히 붙어 움직일 때 느려진다.

- 맞았을 때 화면 가장자리의 붉은 번쩍임이 캡처에서는 꽤 진했다 (0.45초 동안). 실제 화면에서 과하면 `HudUI`의 Hit Flash Alpha(0.3)를 낮춘다.
- 배경 소리 두 개(5초짜리)가 이어질 때 끊기는 느낌이 나는지는 들어 봐야 안다.
- 빌드(`Builds/Windows`)는 이 PC에 없고, 이번 변경 뒤에 다시 빌드하지 않았다.
- `RaidConfig`의 Pods Always Open이 켜져 있다 (테스트용). 끄면 시작 1분 뒤에 열린다. 밸런싱이 끝나면 끄고 다시 빌드한다.
- 맵 확장으로 옛 정거장의 로봇 13기 배치와 사용자가 옮긴 `MeleeRobot 1` 경로는 사라졌다 (새 맵에 맞지 않아 통째로 바꿈).
- 상인과 장거리 포드의 그림은 우주인 그림에 색을 입힌 것과 점 그림이다. 상인 그림을 따로 원하면 무료 팩을 더 찾아야 한다.

- 사용자가 씬에서 `Robots/CargoZone/MeleeRobot 1` 경로를 (0.1, 9)만큼 옮겼다. 그대로 둔다.
- 로봇의 총 사격과 플레이어의 실제 클릭 사격(총소리 발생)은 임시 테스트에서 따로 확인하지 않았다. 총소리는 `GunNoise.Emit`을 직접 불러 확인했다.
